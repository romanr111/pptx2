# pptx-title-slide

Spike/MVP for the larger goal (see `assets/client_goal.rtf`): automatically
turning a doctor's materials into presentations that conform to a conference
template. This skill is now scoped to one job: **measurement**. It derives
build inputs for the title slide from `assets/expected_result/1st_slide{1,2,3}.jpg`
(hand-captured animation states) plus the template and slide copy.

Building the deck, rendering, and verifying against those screenshots now
happen in the **pptx-deck** skill's generic spec-driven pipeline — see
`.claude/skills/pptx-deck/SKILL.md`. This skill only produces the
intermediate measurement artifacts that feed that pipeline's
`geometry_to_spec.py` converter.

## What it produces

`output/work/`:
- `background_title.png` — full-bleed background plate (face art + spheres,
  speaker erased)
- `man_cropped.png` — speaker photo cropped to its alpha bounding box
- `logo_black.png` — template logo recolored black, cropped to alpha bbox
- `geometry.json` — element placements in EMU + measured text metrics
- `content.json` — title lines / speaker name / credential bullets, parsed
  from `assets/slides_text.rtf`

## How to run

```bash
# 1. one-time setup: venv (.venv/), python-pptx/Pillow/numpy/jsonschema, and
#    install the assets/fonts TTFs into ~/Library/Fonts (needed for faithful
#    render)
.claude/skills/pptx-title-slide/scripts/setup_env.sh

# 2. derive measurement artifacts from assets -> output/work/
.venv/bin/python .claude/skills/pptx-title-slide/scripts/extract_assets.py

# 3. freeze those measurements into a spec (pptx-deck skill)
.venv/bin/python .claude/skills/pptx-deck/scripts/geometry_to_spec.py

# 4. build + verify via the generic pipeline (pptx-deck skill)
.venv/bin/python .claude/skills/pptx-deck/scripts/build_deck.py specs/title_slide.spec.json --states
.venv/bin/python .claude/skills/pptx-deck/scripts/verify_reference.py
```

Requires LibreOffice (`soffice` on PATH) for rendering. `extract_assets.py`
takes ~90 s (template-matching the speaker photo); the others seconds.

## Tuning knobs

- Fonts/sizes/tracking/animation choreography: constants at the top of
  `.claude/skills/pptx-deck/scripts/geometry_to_spec.py` (moved out of a
  `build_pptx.py` that no longer exists — the builder is now generic). The
  static TTFs in assets declare family `Geologica Roman <Weight>` (not
  "Geologica") — reference them exactly, otherwise renderers silently fall
  back.
- Geometry/colors: `output/work/geometry.json`, regenerated by
  `extract_assets.py`; per-element positions in EMU (4762.5 EMU/px at the
  2560x1440 reference canvas).

## Spike limitations (known, accepted)

- The woman-face background art and the black horizontal logo exist only in
  the expected screenshots (not among the assets/template media), so both
  are lifted from the screenshots at 2560x1440. Production would need the
  original artwork.
- Title font is matched as Geologica Roman SemiBold + 0.5 pt tracking; the
  expected deck's exact font build differs by ±2 % per-line width. Verified
  imperceptible visually.
- Verification renders with LibreOffice; PowerPoint parity of the timing XML
  is by construction (mirrors the template's own slide 24 animation markup)
  but hasn't been opened in real PowerPoint on this machine.
